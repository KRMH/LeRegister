- (decision) Phone numbers: all international formats accepted (supersedes PRD open Q5)
- (constraint) Inherited from PRD: Telegram Bot API, official libraries only; owner-only allowlist; fixed-grammar rule-based parser (no AI); never delete, append-only Journal; daily backup keep 7; Morning Summary 08:00; 1-min SLA on register/alert; zero running cost

- (decision) Paradigm: hexagonal (ports and adapters) core with append-only journal. Binds all FRs. Prevents domain rules leaking into Telegram/Trello/SQLite code. Adapters: telegram, sqlite store, trello projection, scheduler, backup
- (decision) AD SQLite is single system of record; Trello is one-way rebuildable projection, never read back. Prevents two sources of truth and Trello outages/limits endangering data (FR-8, FR-12)
- (decision) AD No-delete enforced in storage: SQLite triggers abort DELETE on bookings/journal and UPDATE on journal; bookings mutate only status/superseded_by. Prevents a code path deleting (FR-6,7,8)
- (decision) AD One Command = one transaction writing state + journal rows; side effects (Telegram reply, Trello sync, alert) run after commit from an outbox. Telegram updates processed strictly sequentially; update_id stored for idempotency. Prevents racy overlap checks, lost journal entries, duplicate records on redelivery
- (decision) AD Long polling, not webhook: Bot runs on Owner computer with no inbound port. Telegram queues updates while the bot is offline so commands sent during downtime apply on restart in order
- (decision) AD Dates stored as ISO date, nights are half-open [check_in, check_out); timestamps UTC ISO-8601; 'today' computed in configured IANA timezone. [ASSUMPTION] default timezone Europe/Paris, configurable (resort country unknown)
- (decision) AD Phones normalized to E.164 with phonenumbers; numbers without + parsed with configured default region [ASSUMPTION: FR]; E.164 is Client key. Invalid -> reject
- (decision) AD Parser: own deterministic grammar and FR/EN month table; no dateparser, no LLM (heuristics guess; PRD forbids guessing). Pure function, no I/O. Ambiguous -> reject with reason
- (decision) AD Auth: numeric Telegram user id allowlist in config checked at the single entry before parsing; private chats only; all others dropped silently
- (decision) AD Scheduling via PTB JobQueue (APScheduler) in-process: Morning Summary 08:00 local and daily backup. On startup, if today's summary not yet sent (journal event) and it is before 12:00 [ASSUMPTION], send it late and say so. Prevents silent missed summary when computer was asleep and duplicate sends
- (decision) AD Backup: SQLite online backup API to a configured directory, daily, keep 7; backup dir must be on a different location than the live DB (e.g. synced cloud folder or external drive); startup warns if same volume. Restore = documented script/steps
- (decision) AD Trello board mapping: one board named 'LeRegister - Phone bookings only'; lists Active / Overlap / Changed / Cancelled; one card per booking, never archived or deleted; booking id in card description; trello_card_id kept in SQLite; sync idempotent by booking id. Sync failure retried with backoff, owner told after 3 failures (FR-8)
- (decision) AD Secrets (Telegram token, Trello key/token) in env/.env outside repo; never logged
- (decision) Rating stored on client row, changed only with a journal row in same transaction; clamp 1-5
